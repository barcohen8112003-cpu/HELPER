# צוות: חוקר ובודק בתוך Helper

גרסה ראשונה, כבויה כברירת מחדל. Helper מחליט אם בקשה צריכה צוות, מריץ בעצמו כל קריאת כלי, אוכף את המגבלות בקוד ושולח תשובה אחת. כל השאר נשאר במסלול הרגיל (`src/agent.js`) בלי שינוי.

## המסלול

```
הודעת וואטסאפ
  -> whatsapp.js (dedup לפי מזהה הודעה בתהליך)
  -> index.js: פקודות מהירות, "עצור", תור אחד, AbortController, msgId
  -> agent.js runTurn
       -> team/conductor.js conduct()
            TEAM_MODE כבוי / לא בקשת צוות        -> null -> converse() הרגיל (מודל, ניתוב, כלים, אישורים)
            חסרים פרטים                         -> שאלה אחת, המשימה מחכה (state.team.pending)
            יש הכל:
              חוקר  (מודל, רואה רק find_flights) -> מבקש קריאה
                Helper: בודק רשימת כלים, נועל את המגבלות שלו, מזהה פעולה, מריץ find_flights בהקשר מצומצם
              בודק  (מודל, בלי כלים)            -> accept/reject/missing (עצה בלבד)
              בדיקת קוד על נתוני ההצעה עצמם      -> המילה האחרונה
              תשובה אחת מנתוני הכלי, עם המקור
```

החוקר והבודק רצים בזה אחר זה, כי הבודק תלוי בתוצאת החוקר. עומק 1: לעובד אין כלי שפותח עובדים, ובקשה כזאת נחסמת.

## Ruflo: מה נבדק ולמה הוא לא המנוע כאן

נבדקו `ruflo@3.65.1` ו-`@claude-flow/cli@3.65.1` מ-npm (הורדה ופריסה של החבילות בלבד, בלי `npm install`, בלי `init`, בלי הרצה). רישיון MIT, Node 20 ומעלה.

- `agent_execute` (ב-`dist/src/mcp-tools/agent-tools.js`) מקבל `agentId, prompt, systemPrompt, maxTokens, temperature`. אין בסכמה פרמטר כלים, ו-`callAnthropicMessages` שולח `messages: [{ role: 'user', content: prompt }]` בלבד. כלומר עובד של Ruflo לא יכול לבקש את find_flights דרך הממשק הזה.
- הביטול: `AbortController` פנימי ל-timeout בלבד. אין דרך להעביר signal מבחוץ, אז "עצור" של Helper לא יכול לעצור בקשה שכבר נשלחה.
- ספקים: Anthropic, OpenRouter או Ollama בלבד. Helper עובד מול כל API תואם OpenAI (Groq וכו').
- מנסה שוב במודל אחר על 429/5xx (`CLAUDE_FLOW_ROUTER_FALLBACK_MAX_RETRIES`, ברירת מחדל 1), דרך נתב "cost-optimal". זה מגדיל הוצאה מחוץ לתקרה שלנו.
- כותב מצב לדיסק: `.claude-flow/agents/store.json` בתיקייה הנוכחית, וגם רישומי מסלול ולמידה (`ruvector/*`). זה מקור זיכרון נוסף ש-Helper לא מנהל.
- `postinstall` מתקן קבצים בתוך `node_modules/agentdb`. החבילה כבדה (express, sql.js, typescript ועוד).

לכן נבחרה דרך א' מהמפרט: מתאם מקומי קטן, שבו העובד מבקש פעולה מובנית (tool call רגיל) ו-Helper מבצע אותה דרך הכלי הקיים. המודל נקרא דרך `llmOnce` החדש ב-`src/llm.js`: בקשה אחת, מודל אחד, בלי המתנה ובלי מעבר למודל אחר. אם בעתיד רוצים Ruflo, הוא יכול להחליף רק את ה"port" של המודל לתפקיד בלי כלים (הבודק), ורק אחרי שיהיה ביטול מבחוץ וכיבוי של ה-fallback.

## גבולות שהקוד אוכף

- לכל בקשה: עד 4 קריאות מודל, 12,000 טוקני קלט ו-4,000 טוקני פלט מצטברים, 90 שניות. משתני הסביבה יכולים רק להוריד.
- כל קריאה שומרת תקציב לפני שליחה (הערכת קלט שמרנית + תקרת פלט). קריאה שלא נכנסת לא נשלחת. קריאה שנכשלה נשארת בחשבון.
- `TEAM_MODE=live` פועל רק כשמלאים `TEAM_MODEL`, שני המחירים ותקרה לבקשה וליום. אחרת הצוות כבוי. בלי מעבר למודל אחר.
- כלי קריאה בלבד, והחוקר רואה רק את find_flights. כל כלי אחר נחסם ולא מועבר לאישור. ההקשר של הכלי מצומצם: בלי שליחת תמונה, בלי אישורים, בלי סידור בדפדפן.
- המגבלות שלו (קונקשן, לילות, תאריכים, נוסעים) נעולות: מה שהחוקר מבקש אחרת נדרס ונרשם.
- תוצאת כלי עוטפת כ-DATA. הצעה או הערה שנראות כמו הוראה נזרקות ונרשמות.
- dedup לפי מזהה הודעה; מזהה פעולה לכל קריאת כלי. פעולה שהתחילה ולא נרשם סיומה עוצרת את המשימה ("לא ברור") ולא רצה שוב.
- אחרי אתחול: משימה שרצה מסומנת "לא ברורה" ולא רצה שוב לבד. "תחפש שוב" מריץ מחדש.
- ריצת צוות אחת לפרופיל בכל רגע. התור של index.js כבר מונע שני תורות צ'אט במקביל.
- זיכרון ואישורים נשארים במערכת הקיימת. `state.team` מחזיק רק מצב תזמור קצר: משימות אחרונות (עד 50), שאלה ממתינה, הוצאה יומית.

## כיבוי ו-rollback

- `TEAM_MODE` ריק או `off` (ברירת המחדל): `conduct()` מחזיר null בשורה הראשונה, וה-turn ממשיך בדיוק כמו קודם. הבדיקה "flag off" ב-`check:team` מוודאת שהמודל הרגיל עונה ושאין קריאה לצוות.
- הסרה מלאה: revert של ה-PR. השינויים מחוץ ל-`src/team/` קטנים: שלוש שורות ב-`runTurn`, `msgId` ל-ctx ושתי שורות אתחול ב-index.js, `llmOnce` ב-llm.js (פונקציה חדשה, `request` לא השתנה בהתנהגות), `ctx.structured` ב-find_flights (רק כשהצוות מבקש), והגדרות ב-config.js.
