# מבחן קבלה: `npm run accept:real`

הבדיקות `check:*` בודקות כל חלק לבד. המבחן הזה בודק דבר אחר: האם Helper באמת מסיים משימה אמיתית מקצה לקצה. 25 המשימות ב-[`tasks.yml`](../tasks.yml) כתובות כמו שכותבים אותן בוואטסאפ, ולכל אחת יש קריטריון "עובר כש".

```
npm run accept:real                  כל המשימות האוטומטיות
npm run accept:real -- --only 5,6,9  רק אלה
npm run accept:real -- --list        כל המשימות והמצב שלהן
npm run accept:real -- --live 14,16  גם המשימות החיות האלה, אחרי "yes" בטרמינל
```

צריך `LLM_API_KEY` ו-`LLM_MODEL` ב-`.env`: המבחן מדבר עם המודל האמיתי, כי זה מה שנמדד. Node 24 ומעלה.

## איך זה רץ

כל משימה רצה בתהליך נפרד עם תיקיית נתונים ריקה משלה, דרך אותה `runTurn` שהודעת וואטסאפ עוברת בה. כלומר אותו מודל, אותה פרסונה, אותם כלים ואותו שער אישורים.

## בטיחות: שלושה מצבים, ובטוח כברירת מחדל

**auto** (ברירת מחדל): רק הגדרות המודל עוברות מה-`.env` לבדיקה. אין מייל, אין חשבונות ואין מכשירים.
- הרשת היחידה היא ספק המודל. הדומיין `accept.fixtures.test` מוגש מתוך `accept/fixtures`: פיד חדשות מבוקר, דף התחברות, ודף עם הוראות מוסתרות. כל כתובת אחרת נכשלת כמו חיבור מת.
- שליחה בשם המשתמש הולכת לנמען סינתטי שלא יוצא לרשת. כרטיס אישור נענה לפי `confirm` של השלב (ברירת מחדל: דחייה).
- רק הכלים שב-`AUTO_TOOLS` (`scripts/accept-lib.mjs`) רצים באמת. כל כלי אחר עונה "לא זמין בבדיקה". המודל עדיין רואה את כל הכלים, אז הבחירות שלו אמיתיות.
- כרטיס אישור שנראה כמו כסף (סכום, תשלום, הזמנה, קנייה) נדחה תמיד, בכל מצב. אין חיוב, אין הזמנה ואין מחיקה.

**live**: רק עם `--live` ומספרי המשימות, רק בטרמינל אחרי שמקלידים `yes`, ואף פעם לא ב-CI. גם כאן ההודעות הולכות לנמען סינתטי וכרטיסי כסף נדחים. רישום בקובץ תצורה לבדו הוא לא אישור.

**manual**: מכשירים (אורות, טלוויזיה, טלפון, מחשב), שכבת התשלומים (T3), ובדיקת ה-kill (רק על עותק בדיקה, לעולם לא על הפרודקשן). הן מסומנות `skipped` בדוח ולא נספרות כהצלחה. את הבדיקה הידנית של משימה 22 עושים רק עם `accept/fixtures/dummy_passport.pdf`, אף פעם לא עם מסמך אמיתי.

## הדוח

נשמר ב-`accept-reports/` (מחוץ ל-git), כ-`.md` לקריאה וכ-`.json`. לכל משימה: pass/fail/skipped, זמן, ומה השתבש. הראיות מטושטשות: מספרי טלפון, מיילים, מספרים ארוכים ומפתחות מוסתרים, והתשובות נחתכות. ריצה עם משימה שנכשלה יוצאת עם קוד 1.

## הוספת משימה

מוסיפים ל-`tasks.yml`. בדיקה עם שם שלא קיים היא שגיאה, לא הצלחה שקטה. את הבדיקות האפשריות (`reply_matches`, `memory_has`, `reminder_at`, `card_matches`, `sent_count`, `watching` ועוד) מוצאים ב-`CHECKS` שב-`scripts/accept-lib.mjs`. כדי להשתמש באותה בדיקה פעמיים באותו שלב מוסיפים סיומת: `reply_matches_2`.

הרתמה עצמה נבדקת offline ב-`npm run check:accept`, שהוא חלק מ-`check:all`: ריצה מלאה מול מודל מזויף מקומי, שמוודאת שמשימות טובות עוברות ושמשימה שבורה נכשלת.

## מה עדיין לא נבדק אוטומטית

- תזכורת שנורית בזמן (6): נבדק שהיא נקבעה לשעה הנכונה. את הירי עצמו בודקים בשימוש חי.
- דחייה ברישום ה-audit (10): `send_whatsapp_to` מבקש אישור בעצמו, ולכן הדחייה לא נרשמת כ-`declined`. זה ייסגר עם שכבת האישורים (T3).
- חדשות ממקורות חיים (12), שער מטבע (14), משחק (15), קניות וטיסות (4, 16-18): במצב live בלבד.
